# Как работает команда Qalqan

Команда — 3 человека. Каждый работает со своим ИИ-агентом:

| Кто | Агент | Роль |
|---|---|---|
| Лид команды | Claude Code | ведущий разработчик: архитектура, ядро, интеграция, ревью и merge |
| Участник A | Codex | данные и качество детектора |
| Участник B | Codex | панель антифрода, затем презентация |
| — | Codex-ревьюер | автоматическая проверка каждой задачи (`scripts/codex-review.sh`) |

## Зоны (кто какие файлы меняет)

Два человека/агента не правят одни и те же файлы одновременно. Вне своей зоны — только
через описание в PR или задачу лиду.

| Зона | Владелец | Файлы |
|---|---|---|
| Ядро и контракты | Лид + Claude Code | `src/lib/**` (кроме `src/lib/dashboard/**`), `src/app/api/**`, `src/app/bank/**` (мок приложения), `scripts/db-seed.ts`, `scripts/codex-review.sh`, конфиги, `package.json`, `AGENTS.md`, `CLAUDE.md`, `README.md` |
| Данные и качество | Участник A + Codex | `data/dataset/**`, `data/README.md`, `tests/eval/**` (скрипт `scripts/eval.ts` и `docs/metrics.md` ведёт лид) |
| Панель антифрода | Участник B + Codex | `src/app/dashboard/**`, `src/components/dashboard/**`, `src/lib/dashboard/**`, `tests/dashboard/**` |
| Презентация (с 18 ноября) | Участник B | `docs/presentation/**` |

**Общие контракты** (меняет только лид): `src/lib/domain.ts` (типы, схемы
мошенничества, контракт `/api/analyze`), `src/lib/db/schema.ts` (таблица `cases`),
`src/lib/detector/index.ts` (сигнатура `analyzeMessage`), зависимости в `package.json`.

## Процесс

1. Получи свежий `main`: `git pull`.
2. Ветка от `main`: `git switch -c <зона>/<кратко>` — например `data/kk-examples`,
   `dashboard/case-card`.
3. Работай в своей зоне. Коммиты небольшие, сообщения на русском или английском.
4. Перед PR: `npm run check` (lint, типы, тесты, проверка набора) — должен проходить.
5. Push ветки и pull request в `main`. В описании: что сделано, как проверить,
   что не проверено.
6. Лид (Claude Code) прогоняет проверку Codex-ревьюера, оставляет замечания,
   после исправлений делает merge. Максимум 3 цикла проверки на задачу.
7. Push напрямую в `main` не делаем.

## Стартовые задачи

**Участник A — данные и качество**
- Проверить и при необходимости исправить казахские тексты в `data/dataset/messages.jsonl`
  (естественность, грамматика).
- Расширить набор до 150+ записей: больше казахских примеров, больше «ловушек»
  (`hardNegative`: настоящие уведомления банка, похожие на мошеннические), смешанная
  речь RU+KZ, примеры расшифровок звонков.
- Скрипт оценки уже есть: `npm run eval` (см. `docs/metrics.md`). Честная цифра считается на
  `data/dataset/challenge-2.jsonl` — по нему правила не настраиваем.
- Написать ещё один независимый набор `data/dataset/challenge-3.jsonl` (другие сюжеты и
  формулировки), не заглядывая в `src/lib/detector/rules.ts`.

**Участник B — панель антифрода** (`/dashboard`)
- Список случаев из таблицы `cases` (фильтры: статус, тип схемы, язык, риск), сортировка
  по времени.
- Статистика: количество по типам схем, доля отменённых переводов, сумма
  предотвращённых потерь (`outcome = cancelled_by_client`), динамика по дням.
- Карточка случая `/dashboard/cases/[id]`: фрагмент, причины, рекомендация, перевод,
  исход; смена статуса (`new → reviewing → confirmed_fraud / false_positive`).
- Данные: `npm run db:seed`. Запросы к базе — в `src/lib/dashboard/`, клиент — `getDb()`
  из `src/lib/db/client.ts`. Интерфейс на русском.

## Codex в своей зоне

Codex читает `AGENTS.md` автоматически. Хорошее задание для него: зона, файлы, критерии
готовности и `npm run check` в конце. Codex не меняет общие контракты и чужие зоны.
