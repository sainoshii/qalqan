# Качество детектора

Порог вмешательства: `riskScore >= 70`; предупреждение: `riskScore >= 40`.
Все наборы синтетические (см. `data/README.md`). Режим без LLM (в демо LLM не подключена).

## Итог на независимых наборах

Два набора по 40 сообщений (20 мошеннических, 20 обычных; 20 RU, 20 KZ), написаны
независимым ревьюером (Codex), не видевшим ни правил, ни обучающих данных. Обучающий скрипт
отказывается их читать — и по имени файла, и по содержимому (копия или ссылка под другим
именем тоже отклоняются).

| Набор | Версия | Вмешательство: поймано / ложные | Хотя бы предупреждение: поймано / ложные |
|---|---|---:|---:|
| `challenge-2` | только правила | 20% / 5% | — |
| `challenge-2` | **правила + модель** | **55% / 10%** | **95% / 30%** |
| `challenge-4` | только правила | 50% / 15% | — |
| `challenge-4` | **правила + модель** | **80% / 15%** | **100% / 20%** |

Замер 18 ноября, после нормализации записи (казахский и русский в латинице, без казахских букв,
смешанная раскладка). Раньше в этой таблице для `challenge-4` «только правила» стояло 45% — это была
ошибка переноса: базовый замер того же кода 16 ноября дал 50%.

`challenge-4` — самый чистый замер: написан после модели, на нём смотрели только общие цифры
(три раза: при появлении, после варианта A, после общего шаблона «секрет + глагол передачи» —
изменения делались по находкам ревью, а не по ошибкам этого набора). На нём ложные вмешательства дают правила (15% и без модели), а не модель.

По языкам (вмешательство, поймано / ложные / ложные на «ловушках»):

| Набор | Язык | 16 ноября (до нормализации) | 18 ноября |
|---|---|---:|---:|
| `challenge-2` | русский | 60% / 0% / 0% | 60% / 0% / 0% |
| `challenge-2` | казахский | 30% / 10% / 13% | **50%** / 20% / 25% |
| `challenge-4` | русский | 90% / 30% / 60% | 90% / 30% / 60% |
| `challenge-4` | казахский | 70% / 0% / 0% | 70% / 0% / 0% |

На `challenge-2` у казахского прибавилось одно ложное срабатывание (одно обычное сообщение из десяти;
это же сообщение — «ловушка»). Правила его не дают — в режиме «только правила» ложных столько же,
сколько было (5%); риск до вмешательства поднимает связка правил с моделью. Сообщение не разбиралось:
по правилам отложенного набора тексты не открываются. Подгонки под этот замер не было.

### Журнал замеров на `challenge-2` (насколько он «чистый»)

На `challenge-2` смотрели только общие метрики, без разбора отдельных ошибок, но **четыре
раза**, и общие цифры влияли на выбор подхода (после первого замера добавлены «ловушки»,
отрицания и правило двух сигналов). Поэтому `challenge-2` — уже не полностью независимая
оценка; для неё теперь есть `challenge-4`.

1. Первая версия модели → 85% / 35%. Исправлялось по обучающим данным.
2. Вторая версия → 45% / 10%, 90% / 35%.
3. + `train-3` от участника команды, правила не менялись → 45% / 5%, 95% / 30%.
4. Исправления безопасности по ревью (отрицание только в своей фразе, цитаты-инструкции,
   правило двух сигналов на этапе перевода) → те же цифры.
5. Вариант A — однозначные требования засчитываются всегда (без «гашения» отрицаниями и
   цитатами), решение лида после 3 циклов ревью → те же цифры (на `challenge-4` это второй
   замер общими цифрами).
6. Нормализация записи и казахские шаблоны (`kk-normalize`): базовый замер 16 ноября и финальный
   18 ноября, оба — только общие цифры; между ними настройка шла только на обучающих наборах и
   синтетических тестах → 55% / 10%, 95% / 30% (на `challenge-4` это четвёртый и пятый замеры
   общими цифрами: 80% / 15%, 100% / 25%).
7. + `train-4` от участника команды (160 казахских сообщений, 19 ноября), правила не менялись → те же
   55% / 10%, 95% / 30%; на `challenge-4` (шестой замер общими цифрами) вмешательства без изменений
   (80% / 15%), ложных предупреждений меньше: 25% → 20% (русский 50% → 40%). Показатели вмешательства
   на этих двух наборах не изменились; подтверждение правилами ограничивает влияние модели на
   вмешательство, но не исключает его. Казахский — как был (`challenge-2`: 50% / 20%,
   предупреждение 100% / 30%).

## Однозначные требования «на отказ» (вариант A)

Просьба назвать код из SMS, перевести на «безопасный счёт» или установить удалённый доступ
даёт высокий риск **всегда**, как бы ни была построена фраза. Три цикла независимого ревью
показали, что любые правила вида «это отрицание / это цитата из памятки» обходятся подбором
слов («Не спрашивайте зачем и назовите код»). Цена — ложные тревоги на памятках, дословно
повторяющих требование мошенника: на обучающих данных ложных стало 5% вместо 2%, на
независимых наборах цифры не изменились.

Ложные тревоги правила дают не только на памятках, но и на любых фразах, где слово-секрет
стоит рядом с глаголом передачи: «Скажите, когда придёт код», «Код никому не отправьте».
LLM-слой (переменная `ANTHROPIC_API_KEY`) сейчас может **поднять** риск, но не понизить
однозначный признак правил — это защита от текста, пытающегося управлять моделью. Чтобы LLM
снижала такие ложные тревоги, политику объединения нужно будет пересмотреть отдельно.

## Перекрёстная проверка на обучающих данных

`npm run train` — 5 частей, каждый пример оценивает модель, которая его не видела.
С 19 ноября обучающие данные: `messages.jsonl`, `challenge-1.jsonl`, `train-2.jsonl`, `train-3.jsonl`,
`train-4.jsonl` — 604 сообщения, из них 320 от второго автора (240 казахских). На этом наборе:

| Слой | Поймано | Ложные | Верный тип схемы |
|---|---:|---:|---:|
| Только модель, порог 0.6 | 86% | 6% | 81% |
| Правила + модель (как в продукте) | 65% | 5% | 86% |

Набор стал шире (311 мошеннических вместо 211, 160 новых — казахские, треть латиницей), и разбиение
перекрёстной проверки другое, поэтому с цифрами ниже напрямую не сравнивается. На новых примерах
`train-4` связка ловит 43%, модель отдельно — 89%: правило двух сигналов (без подтверждения правилами
модель только предупреждает) может снижать полноту связки, а казахские правила эти формулировки
пока узнают хуже.

До `train-4` — 444 сообщения, из них 160 от второго автора:

| Слой | Поймано (до → после нормализации) | Ложные | Верный тип схемы |
|---|---:|---:|---:|
| Только модель, порог 0.6 | 79% → 84% | 6% → 5% | 72% → 68% |
| Правила + модель (как в продукте) | 69% → 75% | 5% → 5% | 83% → 81% |

Устойчивость к записи — те же обучающие сообщения, автоматически переписанные (правила + модель
«как в репозитории», поэтому цифры завышены; показательна разница между записями):

| Запись | Казахский, поймано из 86 (было → стало) | Русский, из 117 |
|---|---:|---:|
| как в наборе (кириллица) | 60 → 69 | 89 → 89 |
| «упрощённые» буквы (ә→а, қ→к…) | 26 → 69 | — |
| латиница | 24 → 69 | 21 → 82 |
| латинские буквы в кириллическом слове | 15 → 69 | 27 → 89 |

Ложные срабатывания на переписанных обычных сообщениях не выросли (казахский 4/102 в любой записи).

Связка ниже модели по «поймано», потому что правила под тексты второго автора не
настраивались, а правило двух сигналов не даёт модели одной блокировать перевод.

Цифры на обучающих данных выше, чем на `challenge-2`: правила и модель видели похожие
тексты. Показательна именно разница — это и есть честная оценка обобщения.

## Как устроен детектор

0. **Нормализация записи** (`src/lib/detector/normalize.ts`) — латиница, «упрощённые» казахские
   буквы, смешанная раскладка, разрядка и повторы букв приводятся к одной форме; казахские шаблоны
   правил допускают упрощённые буквы только в одну сторону («ә» в шаблоне ловит «а», но не наоборот).
1. **Правила** — объяснимые признаки; однозначные (просьба кода, «безопасный счёт»,
   удалённый доступ) дают высокий риск сами, если в том же предложении нет отрицания.
2. **Статистическая модель** — логистическая регрессия на символьных n-граммах
   (устойчива к опечаткам, транслиту, казахским окончаниям), обучается `npm run train`,
   веса — `src/lib/detector/model-weights.json` (≈340 КБ), работает локально и бесплатно.
3. **Правило двух сигналов**: модель поднимает риск до вмешательства, только если правила
   нашли хотя бы один признак мошенничества; иначе — максимум предупреждение.
4. **LLM** (опционально) — уточняет поверх; при сбое — фолбэк на правила и модель.

## Воспроизвести

```bash
npm run train                                                  # перекрёстная проверка + обучение
npm run eval -- --file data/dataset/challenge-2.jsonl          # правила + модель
npm run eval -- --file data/dataset/challenge-2.jsonl --no-model  # только правила
```
