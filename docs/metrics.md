# Качество детектора

Порог вмешательства: `riskScore >= 70`; предупреждение: `riskScore >= 40`.
Все наборы синтетические (см. `data/README.md`). Режим без LLM (в демо LLM не подключена).

## Итог на независимом наборе `challenge-2`

`challenge-2.jsonl` — 40 сообщений (20 мошеннических, 20 обычных; 20 RU, 20 KZ), написаны
независимым ревьюером, не видевшим ни правил, ни обучающих данных. **По нему ничего не
настраивалось и на нём ничего не обучалось** (обучающий скрипт отказывается его читать).

| Версия | Вмешательство: поймано | Вмешательство: ложные | Хотя бы предупреждение: поймано | …ложные |
|---|---:|---:|---:|---:|
| Только правила | 10% | 5% | — | — |
| Правила + модель, первая версия | 85% | **35%** | — | — |
| **Правила + модель, текущая** | **45%** | **10%** | **90%** | 35% |

По языкам (текущая версия, вмешательство): русский — 60% поймано / 0% ложных,
казахский — 30% / 20%. Казахский слабее: данных меньше.

### Журнал замеров на `challenge-2`

Чтобы цифра оставалась честной, на `challenge-2` смотрели **только общие метрики**, без
разбора отдельных ошибок, и только два раза:

1. Первая версия модели → 85% / 35%. Вывод: модели не хватает разнообразных обычных
   сообщений, похожих на мошеннические. Исправлялось **по обучающим данным**: добавлены
   «ловушки», отрицания в правилах («банк никогда не просит…»), правило двух сигналов
   (одна модель без подтверждения правилами даёт только предупреждение).
2. Текущая версия → 45% / 10% (вмешательство), 90% / 35% (предупреждение).

Для следующего честного замера нужен новый набор — `challenge-3` (пишет другой автор).

## Перекрёстная проверка на обучающих данных

`npm run train` — 5 частей, каждый пример оценивает модель, которая его не видела.
Обучающие данные: `messages.jsonl`, `challenge-1.jsonl`, `train-2.jsonl` (284 сообщения).

| Слой | Поймано | Ложные |
|---|---:|---:|
| Только модель, порог 0.6 | 76% | 9% |
| Правила + модель (как в продукте) | 77% | 0% |

Цифры на обучающих данных выше, чем на `challenge-2`: правила и модель видели похожие
тексты. Показательна именно разница — это и есть честная оценка обобщения.

## Как устроен детектор

1. **Правила** — объяснимые признаки; однозначные (просьба кода, «безопасный счёт»,
   удалённый доступ) дают высокий риск сами, если в том же предложении нет отрицания.
2. **Статистическая модель** — логистическая регрессия на символьных n-граммах
   (устойчива к опечаткам, транслиту, казахским окончаниям), обучается `npm run train`,
   веса — `src/lib/detector/model-weights.json` (≈340 КБ), работает локально и бесплатно.
3. **Правило двух сигналов**: модель поднимает риск до вмешательства, только если правила
   нашли хотя бы один признак мошенничества; иначе — максимум предупреждение.
4. **LLM** (опционально) — уточняет поверх; при сбое — фолбэк на правила и модель.

## Воспроизвести

```bash
npm run train                                                  # перекрёстная проверка + обучение
npm run eval -- --file data/dataset/challenge-2.jsonl          # правила + модель
npm run eval -- --file data/dataset/challenge-2.jsonl --no-model  # только правила
```
