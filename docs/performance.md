# Скорость детектора

Процессор: Apple M5, Node.js v26.10.0, один поток.
Сообщений: 444 × 5 прогонов, средняя длина 156 символов. Каждый замер: правила + модель + оценка перевода, без LLM.

| Замер | Среднее | p50 | p95 | p99 | Максимум |
|---|---:|---:|---:|---:|---:|
| Типичное сообщение, мс | 0.22 | 0.21 | 0.36 | 0.44 | 4.3 |
| Текст 5000 символов, мс | 2.4 | 2.4 | 2.6 | 3.4 | 3.4 |

Пропускная способность в этом замере: **≈ 4 520 проверок в секунду в одном потоке**.

Замер 18 ноября, после нормализации записи (латиница, «упрощённые» казахские буквы, смешанная раскладка). До неё в тех же условиях (ноутбук от батареи, энергосбережение выключено; оба кода подряд) — ≈ 4 970 проверок в секунду: нормализация стоит ≈ 10%. В режиме энергосбережения эта машина вдвое медленнее — сравнивать замеры нужно в одном режиме питания.

Сквозная задержка API — замер версии до нормализации, по сети не перемерялся (qalqan-one.vercel.app; точка входа arn1, функция iad1; режим анализа на сервере: правила + модель, без LLM; 20 последовательных запросов, включая сеть и TLS):

| Среднее | p50 | p95 | Максимум | Ошибок |
|---:|---:|---:|---:|---:|
| 299.5 мс | 251.6 мс | 592.3 мс | 686.2 мс | 0 |

- Проверка не обращается к сети и базе: правила и модель работают в памяти процесса, состояния между запросами нет. Поэтому её можно запускать на нескольких экземплярах параллельно; нагрузочный тест развёрнутого сервиса не проводился.
- Сквозной замер — последовательные запросы одного клиента в пределах лимита API (30 в минуту с адреса); это задержка, а не предельная нагрузка. Она включает сеть, TLS, инфраструктуру Vercel и возможный холодный старт; как она делится между ними, не измерялось. Сама проверка — доли миллисекунды, функция выполняется в регионе Vercel по умолчанию (США).
- С LLM задержка определяется ответом LLM (сотни миллисекунд); поэтому она вызывается только для «серой зоны» (локальный риск 30–69, около четверти сообщений на отложенных наборах).

Воспроизвести: `npm run bench -- --url https://qalqan-one.vercel.app --write`.
